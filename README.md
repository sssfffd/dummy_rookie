# IO Log Scope

엑셀/CSV 로그를 IO 채널 파형으로 그려 주는 Windows 데스크톱 프로그램입니다.
C++17, Win32 + Direct2D, **서드파티 라이브러리 없음**.

```
build/bin/
  logcore.dll    파일 파싱 · 데이터 모델 · 다운샘플링 (UI 코드 없음)
  logscope.exe   Win32 창 + Direct2D 렌더러 (파싱 코드 없음)
```

## 프로젝트 구조에 대해

DLL 과 EXE 가 함께 나오는 이 구성은 이렇게 부릅니다.

- **Visual Studio 관점** — 하나의 **솔루션(solution)** 안에 **프로젝트(project)** 두 개.
  하나는 *동적 연결 라이브러리(DLL)* 프로젝트, 하나는 *Windows 데스크톱
  애플리케이션(EXE)* 프로젝트입니다. 통칭 **다중 프로젝트 솔루션**.
- **CMake 관점** — 하나의 프로젝트에 **타깃(target)** 두 개.
  `add_library(logcore SHARED)` + `add_executable(logscope WIN32)`.
- **설계 패턴으로서** — *코어 라이브러리 + 얇은 호스트 실행 파일* 구조.
  Windows 밖에서는 보통 이걸 "shared library + frontend" 라고 부릅니다.
- EXE 가 DLL 을 쓰는 방식은 **암시적 링크(implicit / load-time linking)** 입니다.
  빌드할 때 생기는 **가져오기 라이브러리(import library, `logcore.lib`)** 를 링크하고,
  실행할 때 로더가 `logcore.dll` 을 올립니다.
  (반대는 `LoadLibrary`/`GetProcAddress` 로 직접 올리는 **명시적 링크**입니다.)

이렇게 나눈 이유는 파싱 코드에 UI 가 섞이지 않게 하기 위해서입니다. 덕분에
파서는 콘솔 도구나 테스트에서 그대로 재사용되고 (`tests/logcore_test.cpp`),
UI 를 손봐도 파싱 로직이 흔들리지 않습니다.

## 빌드

### 미리 있어야 하는 것

1. **Visual Studio 2017 (15.3 이상) / 2019 / 2022** 중 하나 — 설치 관리자에서
   **"C++를 사용한 데스크톱 개발"** 워크로드를 고르세요. MSVC 컴파일러와 Windows SDK 가
   들어옵니다. VS Code 자체에는 컴파일러가 없어서 이건 반드시 필요합니다.
   (15.3 미만이면 `/std:c++17` 이 없어서 구성 단계에서 명확한 오류를 냅니다.)
2. **CMake 3.18 이상** — [cmake.org](https://cmake.org/download/) 에서 받아
   설치 중 *Add CMake to the system PATH* 를 켜세요. Visual Studio 에 딸려 오는
   CMake 는 PATH 에 없는 경우가 많고, VS2017 번들 버전은 대체로 너무 낮습니다.
   `CMakePresets.json` 을 쓰려면 3.21 이상이 필요합니다.

### 확장 없이 쓰기 (VS Code 기본 기능만)

VS Code 확장을 하나도 안 깔아도 빌드는 그대로 됩니다.

- **`Ctrl+Shift+B`** — 기본 빌드 작업이 돕니다. 설치된 Visual Studio 를 자동으로
  찾아 구성하고 Debug 로 빌드합니다. 컴파일 오류는 VS Code 내장 `$msCompile`
  표시기가 잡아서 클릭하면 해당 줄로 갑니다.
- `Ctrl+Shift+P` → **Tasks: Run Task** 에 빌드(Release) · 빌드+테스트 ·
  정리 후 다시 빌드 · 빌드 후 실행이 있습니다.
- 터미널에서 직접:

  ```
  build.bat                     Debug 빌드
  build.bat -Config Release     Release 빌드
  build.bat -Test               빌드 후 테스트
  build.bat -Clean -Run         처음부터 빌드하고 실행
  ```

  `build.bat` 은 `scripts/build.ps1` 을 부르는 얇은 껍데기입니다. PowerShell 실행
  정책이 막혀 있어도 되게 `-ExecutionPolicy Bypass` 를 넣어 뒀습니다.

### 빌드가 안 될 때

**먼저 이것부터.** VS Code 통합 터미널의 기본 셸은 PowerShell 인데, PowerShell 은
현재 폴더의 실행 파일을 그냥 이름만으로 실행하지 않습니다.

```powershell
build.bat      # PowerShell 에서는 동작하지 않습니다
.\build.bat    # 앞의 .\ 가 반드시 필요합니다
```

그래도 이상하면 환경 점검 스크립트를 돌리세요. cmake · Visual Studio · 줄바꿈
문자까지 한 번에 확인하고, 빠진 게 있으면 무엇을 설치해야 하는지 알려 줍니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\diagnose.ps1
```

| 증상 | 원인과 조치 |
|---|---|
| 아무 출력도 없이 프롬프트로 돌아옴 | PowerShell 에서 `.\` 없이 실행했을 가능성이 큽니다. `.\build.bat` 으로 다시 해 보세요 |
| `'build.bat' 용어가 인식되지 않습니다` | 같은 원인입니다 (`.\build.bat`) |
| `cmake 을 찾지 못했습니다` | CMake 3.18+ 를 설치하고 PATH 에 추가하세요. VS 번들 CMake 는 보통 버전이 낮고 PATH 에도 없습니다 |
| `Visual Studio 의 C++ 도구를 찾지 못했습니다` | 설치 관리자에서 "C++를 사용한 데스크톱 개발" 워크로드를 추가하세요. 이미 있다면 `.\build.bat -Generator "Visual Studio 15 2017"` 로 직접 지정 |
| 배치 파일이 이상하게 동작 | 줄바꿈이 LF 로 체크아웃된 경우입니다. `.gitattributes` 가 CRLF 를 강제하므로 `git pull` 후 `git checkout -- build.bat` 로 다시 받으세요 |

`Ctrl+Shift+B` 는 `build.bat` 을 거치지 않고 `powershell.exe` 를 직접 부르므로
위 문제들과 무관하게 동작합니다. 터미널에서 막히면 이쪽을 써 보세요.

**다만 확장 없이는 두 가지가 안 됩니다.**

| 안 되는 것 | 대안 |
|---|---|
| VS Code 안에서 디버깅 (`F5`) | `cppvsdbg` 디버거가 C/C++ 확장에서 오기 때문입니다. **Visual Studio 로 `build\vs2017\LogScope.sln` 을 열어 디버깅하세요.** `logscope` 를 시작 프로젝트로 지정하면 됩니다 — 어차피 Visual Studio 디버거가 VS Code 쪽보다 낫습니다 |
| C++ IntelliSense (정의로 이동, 자동 완성) | VS Code 기본은 단어 단위 완성만 합니다. 코드 탐색이 필요하면 그때만 Visual Studio 를 쓰거나, C/C++ 확장 하나만 설치하는 것도 방법입니다 |

확장을 못 쓰는 이유가 사내 정책이나 마켓플레이스 차단이라면, C/C++ 와 CMake Tools 는
둘 다 Microsoft 가 배포하는 확장이라 `.vsix` 파일을 받아 오프라인 설치도 됩니다
(`code --install-extension <파일>`).

### 컴파일러 옵션과 버전 차이

`/permissive-`, `/Zc:__cplusplus`, `/Zc:preprocessor`, `/DEPENDENTLOADFLAG` 는
Visual Studio 버전마다 있고 없고가 갈립니다. 버전 번호로 짐작하지 않고 구성할 때
**컴파일러·링커에게 직접 물어본 뒤** 받아 주는 것만 붙입니다
(`check_cxx_compiler_flag` / `check_linker_flag`). 그래서 VS2017 에서도 구성이
실패하지 않고, 대신 빠진 완화 기능이 있으면 구성 로그에 경고가 뜹니다.

`/DEPENDENTLOADFLAG` 가 없는 링커라면 정적 임포트 DLL 의 검색 경로가 제한되지
않으므로, **반드시 쓰기 권한이 없는 폴더(`Program Files` 등)에 설치해서 실행하세요**
(`docs/SECURITY.md` 3.1).

[최신 x64 재배포판](https://aka.ms/vs/17/release/vc_redist.x64.exe) 하나면 됩니다).

## 입력 데이터 형식

배치는 두 가지 다 읽습니다. 그리고 **표가 시트 맨 위에서 시작하지 않아도 됩니다.**

### 두 가지 배치

**열 = IO 채널** (시간이 세로로 내려감)

| | B | C | D |
|---|---|---|---|
| **Time [s]** | DI_00_START | AI_TEMP_1 | SEQ_STATE |
| 0.00 | 0 | 182.4 | IDLE |
| 0.01 | 0 | 182.6 | IDLE |
| 0.02 | 1 | 182.5 | RUN |

**행 = IO 채널** (시간이 가로로 감)

| | B | C | D |
|---|---|---|---|
| **IO 이름** | 0.00 | 0.01 | 0.02 |
| DI_00_START | 0 | 0 | 1 |
| AI_TEMP_1 | 182.4 | 182.6 | 182.5 |

### 표가 시트 중간에서 시작해도 됩니다

장비 이름·측정 일시·설정값 같은 머리말이 앞에 붙어 있어도 그대로 읽습니다.

```
A1  장비      주입기 #3
A2  측정일    2026-09-03
A3
A4          Time [ms]   DO_10_MOTOR   AI_PRESS      <- 표는 여기서 시작
A5          0           0             3.1
A6          10          1             42.0
```

**어떻게 찾는가.** 시간축에는 "값이 줄지 않고 길게 이어진다"는 성질이 있습니다.
모든 행과 모든 열에서 그런 구간을 찾아 가장 긴 쪽을 시간축으로 봅니다. 시간축이
행이면 행이 채널, 열이면 열이 채널입니다. 구간이 시작하는 자리가 곧 데이터가
시작하는 자리이고, 그 바로 앞이 이름 행/열입니다.

`CYCLE_COUNT` 처럼 계속 늘어나는 데이터 채널이 시간축을 가로채지 않도록 두 가지
장치를 뒀습니다 — 가장 긴 구간의 90% 이상이면 **더 앞에 있는 쪽**을 택하고,
그 줄을 시간축으로 삼았을 때 **채널이 최소 하나는 남아야** 합니다.

판정 결과는 상태 표시줄에 나옵니다 (`각 열이 IO 채널인 배치로 읽었습니다.
데이터 표가 4행 B열에서 시작하는 것으로 보고 그 앞은 건너뛰었습니다.`).
틀렸으면 툴바에서 **행 = IO** / **열 = IO** 로 직접 지정하면 됩니다.

### 시간축

숫자, `HH:MM:SS.mmm` 문자열, ISO 8601, 엑셀 날짜/시간 셀(`styles.xml` 의 표시
형식을 보고 판별)을 인식합니다. 해석에 실패하거나 값이 증가하지 않으면 샘플
번호(0…N)로 물러서고 상태 표시줄에 그 사실을 알립니다. `Time [s]` 처럼 셀에
단위를 적어 두면 축 라벨에 반영됩니다.

IO 이름이 비어 있으면 `IO_1` 형태로 자동 부여합니다.

**파일 크기 제한은 없습니다.** 자기 로그를 여는 도구이므로 크기를 이유로 거절하지
않습니다. 다만 메모리는 대략 **파일 크기의 3~5배**를 쓰므로, 정말 큰 파일은
`메모리가 부족합니다` 로 실패할 수 있습니다 (거절이 아니라 실제 한계입니다).
외부에서 받은 파일을 다루는 용도로 쓰신다면 `docs/SECURITY.md` 3.7 을 보세요.

지원 확장자: `.xlsx` `.xlsm` `.xltx` `.csv` `.tsv` `.txt` `.log`
(`.xls` 구형 BIFF 는 지원하지 않습니다 — 이유는 `docs/SECURITY.md` 3.5)

### 채널 타입 자동 판별

| 타입 | 판별 기준 | 표현 |
|---|---|---|
| `DIG` | 값이 0/1, TRUE/FALSE, ON/OFF, HIGH/LOW 뿐 | 스텝 파형 + 하이 구간 채움 |
| `ANA` | 값이 모두 숫자 | 라인, 레인별 자동 스케일 |
| `STATE` | 문자열 상태값 | 구간 리본 + 상태 라벨 |

빈 셀은 0 이 아니라 **끊김**으로 처리해 선을 잇지 않습니다. 0 으로 채우면
없는 골짜기가 그래프에 생깁니다.

## 화면과 조작

왼쪽에 채널 목록(검색, `전체/DIG/ANA/STATE/고른 것만` 필터, 개별 체크), 오른쪽에 그래프.
그래프는 두 가지 방식으로 볼 수 있습니다.

### 설정 창 — 오른쪽 위 `설정`

화면 위에 겹쳐 뜹니다. `Esc` 나 바깥을 누르면 닫힙니다.

**판 번호**를 여기서 확인합니다.

```
IO Log Scope  0.01  (a35af0d)
빌드          2026-09-08
설정 파일     C:\Users\...\AppData\Roaming\LogScope\settings.txt
```

판 번호는 `CMakeLists.txt` 의 `LOGSCOPE_VERSION` **한 곳**에서만 나옵니다.
**`0.00` 에서 시작해 고칠 때마다 `0.01` 씩 올립니다.**

커밋 해시는 빌드할 때 git 에서 읽습니다. 같은 판 번호라도 어제 빌드와 오늘 빌드를
해시로 가려낼 수 있습니다 (git 이 없으면 조용히 넘어갑니다).

### 로그 세트 — 여섯 벌

"이전 로그 + 이후 로그" 한 벌이 **세트** 입니다. 여섯 벌을 두고 번호로 오갑니다.

- 오른쪽 위의 `1 2 3 4 5 6` 을 누르면 그 세트의 비교 화면으로 갑니다
- 설정 창에서 세트마다 **이름**과 **기본 폴더 두 개**를 정합니다

| 설정 창의 한 줄 | 뜻 |
|---|---|
| `1번` | 누르면 그 세트로 갑니다 (지금 세트는 눌린 상태) |
| 이름 칸 | 눌러서 그 자리에서 고칩니다. `Enter` 확정, `Esc` 취소 |
| `이전 폴더: …` | **이전 로그 열기** 대화상자가 처음 열릴 폴더 |
| `이후 폴더: …` | **이후 로그 열기** 대화상자가 처음 열릴 폴더 |
| `비우기` | 그 세트가 기억한 폴더와 파일을 지웁니다 (세트 자체는 남습니다) |

폴더를 정해 두지 않으면 예전처럼 **Windows 가 기억하는 마지막 폴더**가 열립니다.

**세트를 바꾸면 그 세트의 로그를 다시 읽습니다.** 여섯 벌을 한꺼번에 메모리에 올려
두지 않습니다 — 로그 하나가 수백 MB 인 자리에서 열두 개를 들고 있으면 그것만으로
메모리가 바닥납니다. 읽는 중에는 세트를 바꿀 수 없습니다 (방금 시작한 읽기가 어느
세트 것인지 알 수 없게 되므로). `읽기 취소` 를 누르고 바꾸면 됩니다.

세트 설정은 `%APPDATA%\LogScope\settings.txt` 에 저장됩니다. 그룹 설정
(`groups.txt`) 과 같은 폴더이고, 형식도 같은 방식입니다.

```
version 1
active	1
set	1	3호기 승온
before-dir	D:\logs\3호기\before
after-dir	D:\logs\3호기\after
before	D:\logs\3호기\before\0901.xlsx
after	D:\logs\3호기\after\0903.xlsx
set	2	4호기
```

### 파일 읽는 동안

큰 `.xlsx` 는 읽는 데 몇 초가 걸립니다. 그동안 창이 멎으면 읽는 중인지 죽은
것인지 알 수가 없으므로, **읽기는 별도 스레드에서 돌리고 창은 계속 움직입니다.**
화면 가운데에 파일 이름, 도는 표시, **경과 시간**, **읽은 줄 수**가 뜨고,
**읽기 취소** 버튼으로 중간에 멈출 수 있습니다.

돌아가는 표시가 멈추지 않고, 줄 수가 늘고 있으면 정상입니다.

### IO 고르기

파일을 열면 **아무것도 선택되지 않은 상태**로 시작합니다. 200채널을 한꺼번에 그려
놓고 지우는 것보다 볼 것을 골라 담는 쪽이 빠릅니다.

### 그룹 — 이름과 구성원을 직접 정합니다

채널은 그룹으로 묶여 있고, 그룹 머리를 눌러 접었다 폈다 합니다. 처음 열면 **10개씩**
자동으로 묶이지만, 이름도 구성원도 원하는 대로 바꿀 수 있습니다.

| 조작 | 결과 |
|---|---|
| 그룹 **이름** 클릭 | 그 자리에서 이름을 고칩니다. `Enter` 로 확정, `Esc` 로 취소 |
| 그룹 머리의 **담기** | 지금 고른 IO 를 그 그룹으로 옮깁니다 |
| 그룹 머리의 **삭제** | 그룹을 지웁니다 (안에 있던 IO 는 **미분류** 로 갑니다) |
| **새 그룹** | 빈 그룹을 하나 만들고 바로 이름을 받습니다. 여기에 IO 를 끌어다 넣습니다 |
| **고른 IO로 새 그룹** | 고른 IO 들로 새 그룹을 만들고 바로 이름을 받습니다 |
| IO 를 **끌어서** 그룹 머리 위에 놓기 | 그 그룹으로 옮깁니다. 여러 개를 골라 둔 상태에서 그중 하나를 끌면 **고른 것이 모두** 따라갑니다 |
| **그룹 머리를 끌어서** 다른 그룹 위에 놓기 | 그 자리로 **그룹 순서**를 옮깁니다 |
| 그룹 머리 클릭 (이름·버튼 밖) | 접기/펴기 |
| 그룹 체크 상자 | 그룹 전체 켜기/끄기 |

**검색으로 그룹 만들기**: 검색창에 `AI_TEMP` 처럼 치고 → **전체 선택** → **고른 IO로
새 그룹**. 이름을 지어 주면 끝입니다.

어느 그룹에도 없는 IO 는 목록 맨 아래 **미분류** 에 모입니다.

**그래프도 목록 차례를 따릅니다.** 그룹 순서를 바꾸거나 IO 를 다른 그룹으로 옮기면
레인과 겹쳐보기에서 그리는 차례도 같이 바뀝니다. 왼쪽에서 보이는 순서와 오른쪽에
그려지는 순서가 어긋나지 않습니다.

### 그룹 설정은 저장됩니다

프로그램을 껐다 켜도 그대로입니다. 다른 파일을 열어도 유지됩니다 — 구성원을 채널
**번호가 아니라 IO 이름**으로 저장하기 때문입니다. 같은 양식의 로그라면 어느 파일을
열어도 같은 그룹이 붙습니다.

저장 위치는 `%APPDATA%\LogScope\groups.txt` 이고, 사람이 읽고 고칠 수 있는 형식입니다.

```
version 1
group	온도
io	AI_TEMP_BARREL1
io	AI_TEMP_BARREL2
group	밸브
io	DO_11_VALVE_A
```

파일을 지우면 **10개씩 묶은 기본값**으로 돌아갑니다. 팀에서 같은 그룹 구성을 쓰려면
이 파일을 복사해 나눠 주면 됩니다.

검색과 타입 필터를 걸면 **전체 선택도 걸린 것만** 대상으로 합니다.

### 고른 것만 — 지금 그래프에 올라온 IO 만 목록에 둡니다

`고른 것만` 을 누르면 그룹을 접어 두고 **켜 둔 IO 만** 늘어놓습니다. 순서는 그래프에
그려지는 차례 그대로라서, 왼쪽 목록을 위에서 아래로 읽으면 오른쪽 파형과 그대로
맞습니다. 200개 중 여덟 개를 골라 보고 있을 때 무엇을 보고 있는지 스크롤해서 찾을
필요가 없습니다.

- 머리의 체크 상자를 누르면 **전부 끕니다** (목록이 비고, 머리는 남습니다)
- 이 상태에서 IO 를 끄면 목록에서도 사라집니다 — 이 목록은 "지금 보고 있는 것" 입니다
- 검색창도 함께 걸립니다

검색 상자는 직접 그린 것입니다 (Win32 자식 컨트롤이 아닙니다). 상자를 눌러
글자 커서를 놓고, `← →` `Home` `End` `Backspace` `Delete` 가 됩니다. `Esc` 는
글자를 지우고, 한 번 더 누르면 검색을 빠져나옵니다. 한글도 그대로 입력됩니다.

### 레인과 겹쳐보기는 무엇이 다른가

| | 레인 | 겹쳐보기 |
|---|---|---|
| 세로 눈금 | **채널마다 따로** | **모든 채널이 하나를 공유** |
| 디지털 | 하이 구간을 칠한 사각 파형 | 다른 채널과 같은 눈금 위의 0 과 1 |
| 쓰임 | 파형을 훑어볼 때 | 값의 크기를 서로 견줄 때 |

**같은 IO 인데 모양이 달라 보이는 것은 이 때문입니다.** 레인은 그 채널의 최소~최대를
레인 높이에 꽉 채우므로 아무리 작은 움직임도 크게 보입니다. 겹쳐보기는 고른 채널
전체를 하나의 눈금에 올리므로, 0~5000 짜리 옆에 놓인 0~1 짜리는 바닥에 붙은 직선이
됩니다. 눈금이 다를 뿐 값은 같습니다.

### 값이 몇천인데 1 만큼 움직이는 것을 보려면

| 방법 | 어디서 | 무엇을 하는가 |
|---|---|---|
| **변화만** | 겹쳐보기 · 세로 눈금 | 채널마다 **기준값(첫 표본)을 뺍니다.** 5000 이던 값이 0 근처가 되고, ±1 의 움직임이 화면을 채웁니다 |
| **보이는 구간에 맞춤** | 레인·겹쳐보기 | 세로 눈금을 전체가 아니라 **지금 보이는 시간 구간**의 최소~최대에 맞춥니다 |
| **값 축 확대** | 겹쳐보기 | `Shift + 휠` 또는 `값 축 확대 ＋`. **커서가 가리키던 값이 제자리에 남도록** 확대합니다 |

셋은 같이 씁니다. `변화만` + `보이는 구간에 맞춤` 이면 대부분 손댈 것 없이 보입니다.

시간축만 확대되고 값은 그대로였던 것이 답답하셨다면 `Shift + 휠` 입니다.
`맞춤` 을 누르면 자동 범위로 돌아옵니다.

### 겹쳐보기 — 가로축 시간, 세로축 값

선택한 IO 들을 **하나의 세로 눈금 위에 겹쳐** 그립니다. 시간에 따라 값이 어떻게
변하는지, 채널끼리 어떻게 맞물리는지 볼 때 씁니다.

- 세로 눈금은 기본적으로 **선택한 채널의 전체 범위로 고정**됩니다. 시간축을 옮기거나
  확대해도 배율이 그대로라, 확대해 놓고 뒤로 넘겼을 때 배율이 풀리지 않습니다.
  작은 흔들림을 보려면 **보이는 구간에 맞춤** 을 켜세요 — 그러면 보이는 구간의 값
  범위에 맞춰 눈금이 따라 좁혀집니다.
- 온도(180대)와 디지털(0/1)처럼 크기가 아주 다른 채널을 같이 볼 때는
  **0–1 정규화** 를 켜면 모양만 비교할 수 있습니다.
- 디지털·상태 채널은 계단으로 그립니다. 비스듬히 이으면 없는 중간 값이 있는 것처럼
  보이기 때문입니다.
- 한 번에 **최대 8개**까지 그립니다. 범주형 색이 여덟 개까지만 서로 구분되기
  때문이고, 더 고르면 앞의 8개만 그리면서 그 사실을 알려 줍니다.
- 마우스를 올리면 그 시각의 채널별 값이 상자로 뜹니다.

### 레인 — 채널마다 한 줄

로직 애널라이저처럼 채널당 한 줄씩 쌓아 각자의 세로 눈금으로 그립니다. 채널이
많을 때 전체를 훑어보기 좋습니다. 레인 왼쪽에 IO 이름, 오른쪽 거터에 커서 위치의
값(아날로그는 최소–최대 범위까지)이 붙습니다.

### 두 로그 비교 — 이전 / 이후

같은 양식으로 뽑은 로그 두 개를 넣으면 **IO 마다 무엇이 달라졌는지** 볼 수 있습니다.

- 툴바의 **이전 로그 열기** → **이후 로그 열기**
- 또는 두 파일을 **한 번에 창에 끌어다 놓기** (첫 번째가 이전, 두 번째가 이후)
- 또는 명령줄: `logscope.exe before.xlsx after.xlsx`

**채널은 이름으로 맞춥니다.** 정확히 같은 이름을 먼저 보고, 없으면 앞뒤 공백과
대소문자를 무시하고 다시 찾습니다. 짝을 못 찾은 채널은 목록에 `없음` 으로 뜹니다.

**시간축은 각자의 시작점을 0 으로 놓고 맞춥니다.** 두 로그의 시각이 같은 기준일
거라고 가정하지 않습니다 — 절대 시각으로 찍힌 로그라면 측정한 날짜부터 다릅니다.
표본 간격이 서로 달라도 됩니다. 이후 로그를 이전 로그의 시간 격자 위로 다시
읽어 오는데, **아날로그는 선형 보간, 디지털·상태는 직전 값 유지**입니다. 디지털을
보간하면 없던 중간 값이 생기기 때문입니다.

**시작 시각이 다를 때 — 정렬.** 트리거 시점이 어긋나 두 로그가 겹치지 않으면
툴바에서 맞출 수 있습니다.

| 버튼 | 하는 일 |
|---|---|
| **◀ ▶** | 이후 로그를 한 표본 간격씩 앞뒤로 민다 |
| **자동 정렬** | 값이 가장 잘 맞는 위치를 찾아 맞춘다 |
| **정렬 해제** | 보정을 0 으로 되돌린다 |

**◀ 앞당김** 은 이후 로그를 시간축에서 앞으로, **뒤로 밀기 ▶** 는 뒤로 옮깁니다
(한 번에 표본 한 칸). 자동 정렬은 이후 로그를 조금씩 밀어 보면서 차이의 합이 가장
작아지는 지점을 찾습니다. 전 구간의 ±40% 를 성기게 훑은 뒤 그 주변을 표본 간격 단위로 다시
봅니다. 적용한 보정값은 상태 표시줄에 나옵니다.

**어느 IO 가 바뀌었는가.** 채널 목록의 오른쪽 표시가 타입 대신 비교 결과로 바뀝니다.

| 표시 | 뜻 |
|---|---|
| `동일` | 두 로그의 값이 같음 |
| `삭제` | 이전 로그에는 있는데 이후 로그에 없음 |
| `신규` | 이후 로그에만 있음 — 목록 맨 아래 **이후 로그에만 있음** 칸에 모아 보여 줍니다 |
| 그 외 | 아래 **차이 기준** 으로 잰 값 |

`달라진 것만` 필터는 값이 바뀐 채널과 **사라진 채널**을 함께 보여 줍니다.
상태 표시줄에는 `이전에만 있음 n · 이후에만 있음 m` 이 늘 떠 있습니다.

### 존재 차이 — 한쪽에만 있는 IO 를 모아 봅니다

`존재 차이` 버튼을 누르면 그룹을 접어 두고 **두 묶음만** 보여 줍니다.

```
▸ 이전 로그에만 있음  (3)      ← 없어진 IO
    DO_11_VALVE_A      삭제
    AI_TEMP_BARREL7    삭제
    ...
▸ 이후 로그에만 있음  (5)      ← 새로 생긴 IO
    DO_42_VALVE_NEW    신규
    ...
```

- **이전 로그에만 있음** 은 그릴 수 있는 IO 입니다. 머리의 체크 상자를 누르면
  **한꺼번에** 켜고 끌 수 있어서, 사라지기 전에 어떤 파형이었는지 바로 봅니다
- **이후 로그에만 있음** 은 이전 로그에 짝이 없어 그릴 수 없습니다. 이름만 보여 줍니다
- 검색창은 두 묶음에 **함께** 걸립니다. `VALVE` 를 치면 양쪽에서 밸브만 남습니다
- 한쪽이 비어 있어도 머리는 `(0)` 으로 남습니다 — "없다" 는 것도 확인해야 할 정보라서

### 차이를 무엇으로 재는가

처음에는 **다른 샘플 수** 하나만 있었는데, `+1 / −1` 이 빠르게 오가는 진동이 있으면
샘플마다 카운트가 올라가서 **사소한 차이가 가장 큰 값으로 보입니다.** 성질이 다른
척도를 함께 두고 툴바의 **차이 기준** 에서 고릅니다. 값은 모두 한 번에 계산해 두므로
기준을 바꿔도 다시 읽지 않습니다.

| 기준 | 재는 것 | 언제 |
|---|---|---|
| **최대** `↕` | 가장 크게 벌어진 순간의 &#124;Δ&#124; | **기본값.** 진동에 가장 둔감합니다. ±1 이 아무리 자주 흔들려도 값은 1 입니다 |
| **평균** | 전체 구간의 평균 &#124;Δ&#124; | 전반적으로 얼마나 벌어졌는지. 짧은 진동은 평균에 묻힙니다 |
| **RMS** | 제곱평균제곱근 | 평균과 비슷하지만 **큰 차이에 더 무게**를 줍니다. 한 번의 큰 이탈을 찾을 때 |
| **면적** `∫` | ∫&#124;Δ&#124;dt | **시간으로 가중**합니다. 오래 벌어져 있으면 크고, 짧은 진동은 작습니다 |
| **시간%** | 다른 시간 / 전체 시간 | 샘플 간격이 다른 로그끼리도 견줄 수 있습니다 |
| **샘플 수** `Δn` | 다른 샘플의 개수 | 처음 방식. **얼마나 자주** 어긋났는지 |
| **구간 수** | 연속으로 다른 구간의 개수 | 값이 크면 한 번의 변화가 아니라 **진동**입니다. 진동인지 판별할 때 |

진동을 아예 세지 않으려면 **허용 오차** 를 올리세요. 값 범위 대비 비율이며 버튼을
누를 때마다 `0.1% → 1% → 5%` 로 돌아갑니다. 이 값보다 작은 차이는 같은 것으로 봅니다
(디지털·상태 채널은 늘 정확히 비교합니다).

**쓰는 요령.** `최대` 로 훑어 크게 벌어진 채널을 찾고, `구간 수` 가 큰데 `최대` 가
작으면 진동입니다. 진동을 걸러내려면 허용 오차를 올리거나 `면적` 으로 보세요.

`달라진 것만` 필터를 누르면 바뀐 IO 만 목록에 남습니다. 아날로그는 값 범위의
1/1000 을 넘게 벌어졌을 때만 다르다고 셉니다 — 그러지 않으면 반올림 차이까지
전부 잡힙니다. 상태 채널은 번호가 로그마다 다르게 매겨지므로 **상태 이름으로**
비교합니다.

**그리는 방식** 은 두 가지입니다.

- **이전+이후** — 둘을 같은 눈금에 겹치고, **두 선 사이를 옅게 칠합니다.** 벌어진
  만큼이 면적으로 보이고, 값이 같은 구간에서는 면적이 0 이라 아무것도 그려지지
  않습니다. **이전은 파랑, 이후는 주황, 음영은 보라** 로 셋 다 다른 색입니다.
  겹쳐보기에서 채널을 여러 개 켤 때 색으로 채널을 구분하고 싶으면
  **색: 채널별** 로 바꾸세요 — 그때는 굵기가 이전/이후를 뜻합니다.
  값이 완전히 같아 두 선이 포개졌는지 확인하려면 **벌려 그리기** 로 이후 선을 살짝
  띄울 수 있습니다 (값은 그대로, 그리는 위치만 옮깁니다).
- **차이 Δ** — 이후에서 이전을 뺀 값만 그립니다. 0 선이 함께 그려져서 어느 쪽으로
  벌어졌는지 보입니다. 상태 채널은 다르면 1, 같으면 0 입니다.

### 조작

| 동작 | 조작 |
|---|---|
| 시간축 확대/축소 | 툴바 **확대 ＋ / 축소 −**, `+` `-` 키, 겹쳐보기에서는 **휠**, 레인에서는 **Ctrl+휠** |
| 전체 보기 | **전체 보기** 버튼, 더블클릭, `0`, Home |
| 시간축 이동 | 드래그, ← → |
| 채널 세로 스크롤 (레인) | 휠 |
| 커서 A / B 놓기 | 클릭 / Shift+클릭 (상태 표시줄에 Δt) |
| IO 선택 | 왼쪽 목록의 체크박스, **전체 선택 / 전체 해제** |
| 보기 전환 | 툴바의 **레인** / **겹쳐보기** |
| 배치 지정 | 툴바의 **자동** / **행 = IO** / **열 = IO** |
| 파일 열기 | 툴바 버튼, Ctrl+O, 창에 드래그 앤 드롭, 명령줄 인자 |
| 두 로그 비교 | **이후 로그 열기**, 또는 파일 두 개를 한 번에 끌어다 놓기 |
| 비교 표시 전환 | 툴바의 **이전+이후** / **차이 Δ** / **벌려 그리기** |
| 두 로그 시간 맞추기 | 툴바의 **◀ ▶** / **자동 정렬** / **정렬 해제** |
| 여러 IO 선택 | 목록에서 **Ctrl+클릭** (하나씩) · **Shift+클릭** (범위) |

조작법은 상태 표시줄 왼쪽에도 늘 적혀 있습니다 (알릴 내용이 없을 때).

휠 한 칸은 **8%** 만 움직입니다. 좁은 구간을 볼 때 한 번에 훌쩍 지나가지 않도록
일부러 완만하게 잡았고, 빠르게 여러 칸 굴리면 그만큼 크게 움직입니다.

버튼은 창이 좁으면 **자동으로 줄을 바꿉니다.** 버튼과 글자가 서로 겹치지 않게
컨트롤 줄 높이가 늘어납니다.

Windows 의 앱 테마(밝게/어둡게)와 모니터별 DPI 를 따라갑니다.

## 얼마나 빨라야 하는가

큰 로그를 여러 개 켜 놓고 시간축을 끌 때 버벅이지 않는 것이 목표입니다. 두 가지
원칙으로 맞췄습니다.

**① 그리는 비용은 파일 크기가 아니라 창 너비에 묶습니다.**
표본이 픽셀보다 촘촘하면 **픽셀 열마다 최소·최대만** 뽑아 그립니다. 화면 폭이
800픽셀이면 표본이 20만 개든 200만 개든 찍는 점은 800열분입니다 — 한 픽셀 안에서
수천 번 오르내리는 구간은 어차피 눈으로 셀 수 없고, 좁은 펄스는 그 열이 통째로
세로로 서기 때문에 사라지지 않습니다. 아날로그·디지털·상태·겹쳐보기·비교 곡선에
모두 적용됩니다.

**② 시각이 커지기만 하는 자리에서는 이진 탐색을 하지 않습니다.**
두 로그를 견줄 때 이전 로그의 표본마다 이후 로그를 다시 뽑아야 하는데, 예전에는
표본마다 이진 탐색과 DLL 호출이 붙었습니다. 시각이 늘 커지기만 하므로 커서를 앞으로
밀기만 하면 됩니다 (`src/app/walker.h`).

| 표본 20만 개 · 채널 1개 | 이진 탐색 | 커서 |
|---|---|---|
| 이후 로그 값 읽기 | 14.2 ms | **1.1 ms** |
| 채널 200개로 치면 | 2.9 초 | **0.2 초** |

값은 두 방식이 **완전히 같습니다** — 테스트가 `lc::sample_at` 과 한 값씩 맞춰 봅니다.
실제로는 비교 통계를 낼 때 표본마다 이진 탐색을 **세 번** 했고, 상태 채널은 표본마다
문자열을 두 개씩 만들어 견줬습니다. 상태 번호는 이제 로그를 열 때 이름으로 맞춘 표를
한 번만 만들어 두고 번호로만 비교합니다.

**겹쳐 그릴 때 이후 로그는 그 로그의 표본 그대로 그립니다.** 이전 로그의 시간 격자에
맞춰 다시 뽑지 않습니다. 빠를 뿐 아니라, 이후 로그가 더 촘촘할 때 그 사이가 잘려
뭉툭해 보이던 것도 없어집니다.
