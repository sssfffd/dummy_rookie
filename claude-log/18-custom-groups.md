## 답변

### 핵심 결정 — 구성원을 이름으로 저장합니다

그룹이 지금까지는 **암묵적**이었습니다. "채널 번호 ÷ 10" 이 곧 그룹이라 이름도
구성원도 바꿀 수가 없었습니다. 명시적인 그룹 목록으로 바꿨습니다.

구성원을 **채널 번호가 아니라 IO 이름으로** 들고 있는 것이 이 기능의 핵심입니다.
번호로 저장하면 다음에 연 파일의 채널 순서가 조금만 달라져도 그룹이 엉뚱한 IO 를
가리킵니다. 이름으로 두면 같은 양식의 로그라면 **어느 파일을 열어도 그대로**
붙습니다. "저장돼서 유지되게" 라는 요구를 실제로 쓸모 있게 만드는 부분입니다.

### 조작

| 조작 | 결과 |
|---|---|
| 그룹 **이름** 클릭 | 그 자리에서 고칩니다. `Enter` 확정, `Esc` 취소 |
| 그룹 머리 **＋** | 고른 IO 를 그 그룹으로 |
| 그룹 머리 **×** | 그룹 삭제 (IO 는 **미분류** 로) |
| **고른 IO로 새 그룹** | 새 그룹을 만들고 바로 이름 입력 상태로 |
| IO 를 **끌어서** 그룹 위에 놓기 | 그 그룹으로 이동. 여러 개 골라 뒀으면 **다 따라감** |
| 그룹 머리 클릭 (이름·버튼 밖) | 접기/펴기 |

**검색으로 그룹 만들기**: 검색창에 `AI_TEMP` → **전체 선택** → **고른 IO로 새 그룹**.

한 IO 는 한 그룹에만 들어갑니다. 다른 그룹으로 옮기면 원래 있던 곳에서 빠집니다.
어느 그룹에도 없으면 맨 아래 **미분류** 로 모입니다.

### 저장

`%APPDATA%\LogScope\groups.txt` 에 UTF-8(BOM) 로 씁니다. 사람이 읽고 고칠 수 있는
형식이라, 잘못되면 지우면 됩니다 (지우면 10개씩 묶은 기본값으로 돌아갑니다).
팀에서 같은 구성을 쓰려면 이 파일을 복사해 나눠 주면 됩니다.

```
version 1
group	온도
io	AI_TEMP_BARREL1
group	밸브
io	DO_11_VALVE_A
```

그룹을 고칠 때마다 즉시 저장합니다. "저장" 버튼은 없습니다.

### 곁들여 정리한 것

검색창과 그룹 이름이 **같은 입력 코드**를 씁니다. 어느 쪽을 고치고 있는지만
`EditTarget` 으로 구분하고, 글자 입력·커서 이동·IME 위치는 한 벌만 있습니다.

채널 줄은 이제 **손을 뗄 때** 판정합니다. 누르는 순간 바로 켜고 끄면 끌어서 옮기는
동작과 구분할 수 없기 때문입니다. 5픽셀 넘게 움직이면 드래그, 아니면 클릭입니다.

### 검증

mingw 크로스 빌드 Debug/Release **경고 0**, 코어 테스트 162개 통과.

**작업 중 제가 또 코드를 지나치게 지웠습니다.** 인덱스 구간으로 잘라 바꾸는 방식을
쓰다가 그 사이에 있던 함수 **21개**(파일 읽기·두 로그 비교·레인 계산)가 통째로
날아갔고, 링크 오류로 드러났습니다. 이번에는 이전 커밋에서 각 함수를 이름으로
찾아 그대로 복원했고, **이전 커밋에 있던 정의가 하나도 빠지지 않았는지, 헤더에
선언만 있고 정의가 없는 것은 없는지**를 기계적으로 확인했습니다. 앞으로는 구간
삭제 대신 이 확인을 매번 돌리겠습니다.

**화면과 저장 동작은 눈으로 보지 못했습니다.** 특히 다음이 실제 확인 대상입니다.

- 그룹 이름을 눌렀을 때 바로 고쳐지는지, 한글이 들어가는지
- IO 를 끌어다 놓는 것이 손에 맞는지 (지금은 5픽셀 이상 움직이면 드래그로 침)
- 껐다 켰을 때 그룹이 그대로 있는지 (`%APPDATA%\LogScope\groups.txt` 확인)
- ＋ / × 버튼 위치가 좁지 않은지
