## 답변

### 1. C4146 — 컴파일 오류

```cpp
const unsigned doy = (153u * (m + (m > 2 ? -3u : 9u)) + 2u) / 5u + d - 1u;
//                                       ^^^^ 부호 없는 값에 단항 빼기
```

날짜 변환 함수(`days_from_civil`)에 있던 `-3u` 입니다. MSVC 가 C4146 을 내고,
저희가 켜 둔 `/sdl` 이 이를 **오류로 승격**시킵니다. 뺄셈을 밖으로 빼서 부호 없는
연산만 남겼습니다.

```cpp
const unsigned mp = (m > 2) ? (m - 3u) : (m + 9u);
const unsigned doy = (153u * mp + 2u) / 5u + d - 1u;
```

같은 패턴이 더 있는지 전수 검사했고, 나머지 한 곳은 이항 뺄셈이라 문제없습니다.

### 2 + 3. 배치 자동 감지 — 열이 IO 채널이고, 표가 시트 중간에서 시작

두 요구는 사실 한 문제입니다. **표가 어디서 시작하고 어느 방향인지**를 찾아야
합니다. 기존 코드는 "A1 이 헤더, A열이 이름"을 못박아 두고 있었습니다.

**푼 방법.** 시간축에는 *값이 줄지 않고 길게 이어진다*는 성질이 있습니다. 모든
행과 모든 열에서 그런 구간을 찾아 **가장 긴 쪽을 시간축**으로 봅니다.

- 시간축이 **행**이면 → 행이 채널, 그 행이 헤더, 구간 시작 바로 왼쪽이 이름 열
- 시간축이 **열**이면 → 열이 채널, 그 열이 시간, 구간 시작 바로 위가 이름 행

구간이 시작하는 자리가 곧 데이터가 시작하는 자리이므로, **머리말 건너뛰기가
공짜로 따라옵니다.** 찾은 위치 앞을 잘라내고 필요하면 전치한 뒤, 기존 로직을
그대로 태웁니다.

```
A1  장비      주입기 #3
A2  측정일    2026-09-03
A3
A4          Time [ms]   DO_10_MOTOR   AI_PRESS     <- 4행 B열에서 시작한다고 판정
A5          0           0             3.1
```

**오탐을 막는 장치 두 가지.** 처음 구현했을 때 `CYCLE_COUNT` 같이 계속 늘어나는
데이터 채널이 시간축으로 뽑히는 문제가 실제로 났습니다.

1. 가장 긴 구간의 90% 이상이면 **더 앞에 있는 줄**을 택합니다 (헤더가 데이터보다 위에 있음)
2. 그 줄을 시간축으로 삼았을 때 **채널이 최소 하나는 남아야** 합니다

2번은 테스트를 돌리다 **세그폴트**로 드러났습니다. 헤더에 해석 가능한 시간이
없는 시트에서 마지막 데이터 행이 시간축으로 뽑혔고, 잘라내고 나니 채널이 하나도
안 남았습니다. AddressSanitizer 로 위치를 잡아 제약을 추가했습니다.

시간축을 아예 못 찾으면 (시간이 `T1`, `T2` 같은 문자열인 경우) 대비책으로
**채워진 칸이 갑자기 많아지는 첫 행**을 표의 시작으로 봅니다. 머리말은 건너뛰되
배치는 사용자 설정을 따릅니다.

### 달라진 것

- `LcOrientation` 이 **AUTO / ROWS / COLS** 3단이 되고 **AUTO 가 기본**입니다
- 툴바 토글도 **자동 / 행 = IO / 열 = IO** 3단
- 판정 결과가 상태 표시줄에 나옵니다 —
  `각 열이 IO 채널인 배치로 읽었습니다. 데이터 표가 4행 B열에서 시작하는 것으로 보고 그 앞은 건너뛰었습니다.`
- 새 ABI: `lc_orientation()`, `lc_data_first_row()`, `lc_data_first_column()`

### 검증

테스트를 **71개 → 111개**로 늘렸고, AddressSanitizer + UndefinedBehaviorSanitizer
아래에서 전부 통과합니다. 새로 넣은 것:

- 열이 IO 채널인 배치를 자동으로 알아내는가
- 머리말이 붙어 4행 B열에서 시작하는 표 (열 배치 / 행 배치 각각)
- 단조 증가하는 카운터가 시간축을 가로채지 않는가
- 배치를 직접 지정하면 자동 판정을 무시하고 따르는가

mingw 크로스 빌드도 Debug/Release 둘 다 통과했고, 새 ABI 3개가 DLL 에서
export 되는 것까지 확인했습니다.
