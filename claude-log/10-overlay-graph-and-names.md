## 답변

### 1. 겹쳐보기 — 가로축 시간, 세로축 값

C++ 앱에는 레인 보기(채널마다 한 줄, 각자 눈금)만 있었습니다. 요청하신 **하나의
세로 눈금 위에 여러 IO 를 겹쳐 그리는** 방식을 새로 만들었습니다.

- 세로 눈금은 **지금 보이는 시간 구간**의 값 범위에 맞춥니다. 확대하면 눈금도 같이
  좁혀져서 작은 흔들림까지 보입니다.
- **0–1 정규화** 토글 — 온도(180대)와 디지털(0/1)처럼 크기가 아주 다른 채널을
  나란히 볼 때 모양만 비교할 수 있습니다.
- 디지털·상태 채널은 **계단**으로 그립니다. 비스듬히 이으면 없는 중간 값이 있는
  것처럼 보입니다.
- 마우스를 올리면 그 시각의 채널별 값이 상자로 뜹니다.
- 한 번에 **최대 8개**. 범주형 색이 여덟 개까지만 서로 구분되기 때문이고, 더 고르면
  앞의 8개만 그리면서 그 사실을 화면에 적습니다.

### 2. IO 선택과 확대·축소

IO 선택은 왼쪽 목록의 체크박스로 이미 되고 있었고, 겹쳐보기가 그 선택을 그대로
씁니다. 확대·축소도 이미 `Ctrl+휠` 로 있었지만 **어디에도 안 적혀 있어서 없는 것과
같았습니다.** 그래서:

- 툴바 아래 **컨트롤 줄**을 새로 만들고 **＋ / — / 전체 보기** 버튼을 넣었습니다
- 컨트롤 줄 오른쪽에 조작법을 늘 표시합니다
- 겹쳐보기에서는 세로로 스크롤할 것이 없으므로 **그냥 휠을 굴려도 확대**됩니다

### 3. IO 이름이 IO_1 로 나오던 문제 — 진짜 버그였습니다

말씀하신 모양(머리말이 있고, A열은 비어 있고, 표는 B열부터, IO 이름은 한 행에
가로로)으로 테스트를 만들었더니 **그대로 재현됐습니다.**

원인은 배치 자동 판정이 **행 배치로 오판**한 것이었습니다. 이 시트의 데이터 행이

```
(빈칸)   0.00   0   0   181.5      <- 우연히 증가 순서
```

처럼 우연히 값이 줄지 않는 순서였고, 길이가 진짜 시간축(0.00, 0.01, 0.02, 0.03)과
**똑같이 4** 였습니다. 동점이면 행 배치를 택하도록 돼 있어서 행으로 읽혔고, 그러면
이름 열이 **텅 빈 A열**이 되어 모든 채널이 IO_1, IO_2 ... 가 됩니다.

**고친 방법 — 길이보다 이름을 먼저 봅니다.** 각 배치를 택했을 때 채널 이름이 실제로
채워지는 비율을 계산하고, 한쪽만 이름이 제대로 붙으면 길이와 무관하게 그쪽을
택합니다. 위 시트에서는 행 배치가 0%, 열 배치가 100% 라 열 배치로 갑니다.

**덤으로**, 이름 칸이 정말 비어서 임시 이름을 붙인 경우에는 그 사실을 상태
표시줄에 적습니다:

> 이름 칸이 비어 있어 채널 3개에 임시 이름(IO_n)을 붙였습니다. 배치가 맞는지 확인해 보세요.

조용히 IO_n 을 달면 원래 이름이 없는 것인지 배치를 잘못 읽은 것인지 구분할 수가
없습니다. 이번에 겪으신 게 정확히 그 상황입니다.

### 검증

테스트 **111개 → 125개**, AddressSanitizer + UBSan 아래 전부 통과. 새로 넣은 것:

- 머리말 + 빈 A열 + 가로로 늘어선 IO 이름 시트에서 **엑셀에 적힌 이름이 그대로**
  들어오는가 (`DI_00_CYCLE_START` 등)
- 이름이 정말 비었을 때 그 사실을 알리는가

mingw 크로스 빌드 Debug/Release 모두 경고 없이 통과.
