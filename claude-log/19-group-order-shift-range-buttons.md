## 답변

### 1. Shift 범위 선택 — 진단이 정확하셨습니다

범위를 **채널 번호**로 잡고 있었습니다.

```cpp
const uint32_t lo = min(anchorChannel_, ch);
const uint32_t hi = max(anchorChannel_, ch);
for (uint32_t i = lo; i <= hi; ++i) selected_[i] = true;   // 파일 순서
```

그룹 순서를 바꾸거나 IO 를 다른 그룹으로 옮기면 **화면 순서와 채널 번호가
어긋납니다.** 그래서 눈에 보이는 것과 전혀 다른 묶음이 잡혔습니다. 말씀하신
"바꾸기 이전 순서로 선택된다" 가 바로 이것입니다.

**화면에 그려지는 줄 목록(`railRows_`)에서 위치를 찾아** 그 사이를 고르도록
고쳤습니다. 이제 보이는 그대로 잡힙니다.

기준점이나 클릭한 채널이 접힌 그룹 안에 있어 목록에 없으면 예전처럼 번호 범위로
물러섭니다.

### 2. 그룹 순서 바꾸기

**그룹 머리를 끌어서** 다른 그룹 위에 놓으면 그 자리로 옮겨집니다. 순서도 바로
저장됩니다.

접기/펴기와 겹치지 않게, 그룹 머리에서 **끌면 순서 이동, 끌지 않고 떼면
접기/펴기** 로 나눴습니다 (채널 줄에 이미 쓰던 방식과 같습니다). 이름·＋·×·체크
상자는 누르는 즉시 동작하므로 영향이 없습니다.

**미분류** 는 옮길 수 없고, 다른 그룹을 미분류 자리에 놓으면 맨 뒤로 갑니다.

### 3. 버튼이 튀어나오던 것

레일 버튼에 **줄바꿈이 아예 없었습니다.** 컨트롤 줄만 고쳐 놓고 레일은 빠뜨렸는데,
지난번에 `고른 IO로 새 그룹` 을 추가하면서 5개가 되어 레일 폭을 넘겼습니다.

- 레일 버튼도 자리가 모자라면 **줄을 바꿉니다**
- 버튼 하나가 통째로 레일보다 넓으면 **잘라서** 밖으로 나가지 않게 합니다
- 목록이 시작하는 높이를 **실제 배치 결과에서 가져옵니다.** 예전에는 손으로
  추정한 값이라 버튼이 하나 늘 때마다 목록과 겹쳤습니다 — 겹침 신고가 반복된
  진짜 원인입니다

필터 칩과 선택 버튼은 서로 다른 줄에서 시작하도록 명시적으로 나눴습니다.
