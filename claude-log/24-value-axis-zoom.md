## 요청

> 이거 겹쳐보기 했을 때 왼쪽에 숫자 뜨는 거랑 그래프 높낮이 비율에 안맞는 것 같음
> 그리고 레인이랑 겹쳐보기 그래프 차이 뭐임 그래프 모양이 다른데?
> 그리고 겹쳐보기에서 확대를 하다보면 그래프 차이난다고 보여주던게 갑자기 사라지는 경우도 있고
> io범위가 몇천일때 1정도 바뀌는 것도 차이를 확인하고 싶은데 잘 보이지도 않고
> 확대했을때 시간만 확대되고 밸류는 확대되는거 아니여서 확인이 힘드네

## 답변

### 1. 눈금과 그림이 어긋난 것 — 진짜 버그였습니다

겹쳐보기의 **이후 곡선과 차이 띠가 세로 눈금 변환을 거치지 않고** 있었습니다.

```cpp
// 이전 곡선 (DrawSeries)
yOf(val) = ... SeriesValue(ch, val) ...   // 정규화 등이 걸린다
// 이후 곡선 (DrawResampled) · 차이 띠 (DrawDifferenceBand)
yOf(val) = ... val ...                    // 원래값 그대로  ← 어긋남
```

- **`0–1 정규화` 를 켜면** 이전 곡선은 0~1 로 접히는데 이후 곡선과 차이 띠는 원래
  값(예: 4800) 자리에 그려집니다. 화면 밖이라 **아예 보이지 않습니다** —
  "차이난다고 보여주던 게 갑자기 사라진다" 가 이것입니다
- 왼쪽 축 숫자도 이전 곡선 기준이라 이후 곡선과는 맞지 않았습니다

셋이 같은 변환을 거치도록 고쳤습니다. 범위를 구하는 `OverlayRange` 도 같은 변환을
쓰게 해서, **눈금과 그림이 어긋날 자리 자체를 없앴습니다.**

`0–1 정규화` 일 때 왼쪽 숫자는 이제 **%** 로 나옵니다. 채널마다 뜻이 다른 값을 숫자로
적어 두면 어느 채널의 값인지 알 수 없어서입니다.

### 2. 레인과 겹쳐보기는 눈금이 다릅니다

| | 레인 | 겹쳐보기 |
|---|---|---|
| 세로 눈금 | **채널마다 따로** | **모두가 하나를 공유** |
| 디지털 | 하이 구간을 칠한 사각 파형 | 같은 눈금 위의 0 과 1 |

레인은 그 채널의 최소~최대를 레인 높이에 꽉 채웁니다. 겹쳐보기는 고른 채널 전체를
하나의 눈금에 올리므로, 0~5000 짜리 옆의 0~1 짜리는 바닥에 붙은 직선이 됩니다.
**눈금이 다를 뿐 값은 같습니다.**

### 3. 몇천 중 1 을 보는 방법 — 세 가지를 넣었습니다

이게 이번 요청의 핵심이라고 봤습니다.

| 방법 | 어디서 | 무엇을 |
|---|---|---|
| **변화만** (새로 만듦) | 겹쳐보기 · 세로 눈금 | 채널마다 **기준값(첫 표본)을 뺍니다.** 4800 이던 값이 0 근처가 되고 ±1 이 화면을 채웁니다 |
| **값 축 확대** (새로 만듦) | 겹쳐보기 | `Shift + 휠`, 또는 `값 축 확대 ＋ / 축소 − / 맞춤` |
| **보이는 구간에 맞춤** (레인까지 넓힘) | 레인·겹쳐보기 | 눈금을 전체가 아니라 **지금 보이는 시간 구간**에 맞춥니다 |

- `Shift + 휠` 은 **커서가 가리키던 값이 제자리에 남도록** 확대합니다. 가운데를
  기준으로 확대하면 4800 근처에 있는 신호는 한 번만 굴려도 화면 밖으로 나갑니다
- **변화만** 은 이전·이후 **둘 다 이전 로그의 기준값**을 뺍니다. 각자 자기 기준을
  빼면 두 로그의 차이가 없어져 버립니다
- 기준값은 그 채널의 **첫 표본**입니다. 보이는 구간마다 다시 잡으면 시간축을 옮길
  때마다 그림이 통째로 튀어 오릅니다 (예전에 "시간을 뒤로 보냈을 때 갑자기 배율
  풀리는 게 불편하다" 하신 것과 같은 문제입니다)
- **레인**에도 `보이는 구간에 맞춤` 을 넣었습니다. 예전에는 겹쳐보기에서만 나오는
  버튼이었는데, 값이 4000 대에서 1 만큼 오르내리는 신호는 레인에서도 평평한
  직선이었습니다. 이제 그 움직임이 레인을 가득 채웁니다

`0–1 정규화` 하나였던 세로 눈금 버튼은 **`원래값 / 0–1 정규화 / 변화만`** 셋 중 하나를
고르는 방식으로 바꿨습니다.
