# 20 · 빠진 기능 점검, 한쪽에만 있는 IO 모아 보기

- **날짜** 2026-09-07
- **커밋** [`cc9e4c7`](../../../commit/cc9e4c7) Collect IOs that exist on only one side, and restore two lost behaviors
- **바뀐 파일** `src/app/app.cpp`, `src/app/app.h`, `README.md`

## 요청

> 그리고 이전에 그룹 설정 변경하면서 기능들 많이 빠진 거 같은데 점검해주고
> 이전과 이후 로그 비교할 때 io값의 개수나 이름이 다르면 아래 알려주잖아 근데 그것들 모아서 볼 수 있게 해줘
> 이전만 있는 io 이후만 있는 io 이렇게

## 답변

### 1. 점검 — 두 가지 실제로 빠져 있었습니다

그룹 작업(`70d5f5f`) 전후를 기계적으로 맞춰 봤습니다.

| 점검 항목 | 결과 |
|---|---|
| 그룹 작업 이전에 있던 `App::` 함수가 사라졌는가 | 사라진 것 없음 (없어진 3개는 검색창을 직접 그리게 바꾸며 **의도적으로** 없앤 것) |
| 화면 문구(버튼·라벨)가 사라졌는가 | 사라진 것 없음 |
| 헤더에 선언만 있고 정의가 없는 것 | 없음 |
| **모든 버튼이 실제로 화면에 놓이는가** | **`새 그룹` 이 빠져 있었음** |
| **목록 순서와 그래프 순서가 맞는가** | **어긋나 있었음** |

**빠진 것 ①  `새 그룹` 버튼.** 누르면 동작하도록 코드는 다 들어 있는데 화면에
**놓는 줄이 없었습니다.** 그래서 빈 그룹을 만들 방법이 없었고, IO 를 먼저 고르지
않으면 그룹을 새로 만들 수가 없었습니다. 레일 버튼 줄에 넣었습니다.

**빠진 것 ②  그래프가 목록 순서를 따르지 않았습니다.** 레인과 겹쳐보기가
**파일 안의 채널 번호 순서**로 그리고 있었습니다. 그룹을 만들기 전에는 왼쪽 목록도
번호 순서라 티가 안 났는데, 그룹 순서를 바꾸거나 IO 를 옮기면 **왼쪽에서 보이는
차례와 오른쪽에 그려지는 차례가 어긋납니다.** 목록 차례를 따르도록 고쳤습니다.

한 가지 더: `MetricValue()` 는 지금 아무 데서도 부르지 않습니다. 화면에는 영향이
없지만(표시는 `MetricBadge()` 가 합니다) 그냥 남아 있는 코드입니다.

### 2. 한쪽에만 있는 IO 모아 보기

말씀대로 지금까지는 **흩어져** 있었습니다. 없어진 IO 는 제 그룹 안에 `삭제` 표시로
남아 있고, 새로 생긴 IO 만 목록 맨 아래에 모여 있었고, 개수는 상태 줄 한 줄뿐이었죠.

**`존재 차이`** 버튼을 넣었습니다 (비교 로그를 열었을 때 `달라진 것만` 옆).
누르면 그룹을 접어 두고 두 묶음만 보여 줍니다.

```
▸ 이전 로그에만 있음  (3)      ← 없어진 IO
    DO_11_VALVE_A      삭제
    AI_TEMP_BARREL7    삭제
▸ 이후 로그에만 있음  (5)      ← 새로 생긴 IO
    DO_42_VALVE_NEW    신규
```

- **이전 로그에만 있음** 은 이전 로그에 데이터가 있으므로 **그릴 수 있습니다.**
  머리의 체크 상자를 누르면 한꺼번에 켜집니다 — 없어지기 전 파형을 바로 봅니다
- **이후 로그에만 있음** 은 이전 로그에 짝이 없어 그리지 못합니다. 이름만 보여 줍니다
- **검색창이 두 묶음에 함께 걸립니다.** `VALVE` 를 치면 양쪽에서 밸브만 남습니다
  (이전에는 "이후에만 있음" 칸이 검색을 무시했습니다 — 같이 고쳤습니다)
- 한쪽이 비어도 머리는 `(0)` 으로 남깁니다. "없다" 는 것도 확인해야 할 답이라서
- 두 머리의 색을 그래프의 이전(파랑) · 이후(주황) 색과 맞췄습니다

비교 로그를 닫으면 이 필터는 저절로 풀립니다.
